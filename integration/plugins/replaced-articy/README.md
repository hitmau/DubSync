# REPLACED Articy runtime adapter

`integration/adapters/replaced_articy.py` converts `InitLine` and `ReleaseLine` to DubSync's game-independent event contract. It prefers `Articy ExternalId`; when that field is empty, the game plugin uses the full numeric `DialogueFragment.Id` only if it matches the `ArticyRef.id` received by the callback. It never substitutes `ShortId`, speaker, text, or timestamps. The BepInEx IL2CPP plugin hooks `SadCatStudios.Dialogs.SubtitlesManager.InitLine` and `ReleaseLine` and sends normalized local events to `/api/integration/runtime/events`.

The local test installation currently uses BepInEx IL2CPP x64 build `6.0.0-be.788+5b766a3`. The loader and plugin started successfully, generated 138 interop assemblies, and resolved these game signatures:

- `SadCatStudios.Dialogs.SubtitlesManager.InitLine(ArticyRef, SpeechController, Boolean)`
- `SadCatStudios.Dialogs.SubtitlesManager.ReleaseLine()`

The first installed probe observed `SubtitlesManager.InitLine(ArticyRef, SpeechController, false)` during real gameplay and the corresponding `ReleaseLine()` callbacks. Inspection of the generated game interop assemblies confirms that `ArticyRef` provides `GetObject<T>()`, and `Articy.Replaced.DialogueFragment` exposes `ExternalId`. In the tested game build, `ExternalId` was empty at runtime. The full object ID `72057649872502883` recurred for the same first line after restarting the game. A synchronized game-window capture confirmed that this ID corresponds to “Warren, foi registrada uma hora extra adicional.” The initial REACH mapping was wrong, the failed test was recorded as `wrong_mapping`, and the package was made stale. The corrected mapping uses the approved Warren take `TAKE_B980FCAF8AEA`. The live bridge resolved its `dialogue_start` and `dialogue_end` to that take. An early external-helper smoke check confirmed the packaged OGG and its gain; the current plugin instead plays approved takes through the game's FMOD channel.

Two more game-window captures confirmed `72057649872502892` = “Obrigado por me lembrar pela sexta vez, REACH” (`TAKE_8C14A7F1B118`) and `72057649872502899` = “Sua atividade cerebral está instável” (`TAKE_6051A24FC99D`). Package `PKG_E2C21EF281294CC0` contains these takes plus the first Warren take. Test run `TST_59849A2176A44AC7` is an earlier three-dialogue checkpoint and remains `incomplete` because that run did not meet the 10-dialogue acceptance gate. In a later gameplay session, the user confirmed hearing eight dubbed lines through the in-game player; the 10-dialogue gate remains open.

The game install was not modified by overwriting preexisting game files. The exact list of loader/plugin files added by this test is in the ignored local `.data/replaced-probe-install.json`. Use `scripts/remove_replaced_probe.ps1` to roll them back. Do not check the generated loader or game files into Git.

The plugin emits events only to loopback (`127.0.0.1`) and the project-scoped endpoint stores event IDs, callback names, trigger IDs, and resolution status. Subtitle text is shown in the local BepInEx log, but is not sent to or persisted by the API.

## Automatic approved-take playback

The runtime now reads the `DialogueFragment` text on each `InitLine`, normalizes Unicode, punctuation, accents, and whitespace, then looks for one unique approved take whose OCR source text or edited dubbing text has the same normalized value. An exact text collision is skipped unless the game speaker narrows it to one take. The plugin does not send subtitle text to the API. If no safe text match exists, it can use a previously saved Articy trigger correlation as a fallback; these database correlations and the mapping API are retained, while the manual mapping tab is hidden in the interface.

When a package is generated, DubSync stages it under `BepInEx\plugins\DubSync.ReplacedProbe\packages\<package-id>` and atomically switches `active-package.json`. The pointer also stores one global DubSync channel gain (mute to +30 dB, default 0 dB / 100%), so changing it does not rebuild or re-encode approved takes. The Take Studio slider shows decibels; the plugin stores the equivalent linear percentage and applies the multiplier through FMOD. Values above 0 dB can cause distortion or clipping depending on the source and game's mix. The installed plugin reads that active package and creates/plays the audio through the game's `FMODUnity.RuntimeManager.CoreSystem`, so no per-dialogue ID entry or external `ffplay` process is needed. It applies gain only to DubSync playback; the game master volume still affects all game output. The previous dubbed channel is stopped when the next dialogue begins. The plugin does not mute or duck the game's original voice channel. Subtitle text is included in the local BepInEx log for each observed dialogue and is not sent in runtime API events.

Approving or rejecting a take queues a debounced background package refresh and activates the result in the game folder. Bulk approvals are batched by the debounce window. The integration page's manual package action remains available to force a refresh; new approvals no longer depend on using it.

The matcher/player has been exercised in gameplay, and the user confirmed eight DubSync lines were audible. The acceptance gate still requires at least ten confirmed dialogues. The latest source update adds a separate global DubSync channel-volume control and local subtitle logging; because the game must be closed before replacing the loaded plugin, those latest changes apply after the next plugin update and game launch. Ambiguous, unmatched, or failed playback is logged and skipped rather than selecting an arbitrary take.
